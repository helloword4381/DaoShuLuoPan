# 道枢罗盘 · 自动更新通道（三级降级）

> 对应原始需求文档第 4 节。本文覆盖：三级降级顺序与 URL 规则、`version.json` 字段表、状态机、限流/404/超时处理、APK 下载与未知来源授权、通道排障。
> 相关实现：`app/src/main/java/com/daoshu/compass/data/update/`（`VersionInfo.kt`、`UpdateState.kt`、`UpdateRepository.kt`、`DefaultUpdateRepository.kt`）、`app/src/main/java/com/daoshu/compass/data/install/ApkInstaller.kt`、`release/version.json`。

---

## 一、三级降级顺序

App 依次尝试以下通道，**任一成功即返回**，全部失败才置为 `UpdateState.Failed`：

| 级别 | 枚举值 | 通道说明 | URL |
|------|--------|----------|-----|
| 1 | `UpdateChannel.GHFAST_PROXY` | 主通道·加速代理 | `https://ghfast.top/https://raw.githubusercontent.com/helloword4381/DaoShuLuoPan/main/release/version.json` |
| 2 | `UpdateChannel.RAW_GITHUB` | 备用通道·raw.githubusercontent | `https://raw.githubusercontent.com/helloword4381/DaoShuLuoPan/main/release/version.json` |
| 3 | `UpdateChannel.GITHUB_API` | 最终降级·GitHub Releases API | `https://api.github.com/repos/helloword4381/DaoShuLuoPan/releases/latest` |

URL 由构建期常量拼接，**代码中不硬编码 owner / repo / branch**：

| BuildConfig 字段 | 值 | 来源 |
|------------------|----|------|
| `BuildConfig.GITHUB_OWNER` | `helloword4381` | `app/build.gradle.kts`（`androidComponents.onVariants`） |
| `BuildConfig.GITHUB_REPO` | `DaoShuLuoPan` | 同上 |
| `BuildConfig.GITHUB_BRANCH` | `main` | 同上 |

拼接模板：

```text
通道 1：https://ghfast.top/https://raw.githubusercontent.com/{owner}/{repo}/{branch}/release/version.json
通道 2：https://raw.githubusercontent.com/{owner}/{repo}/{branch}/release/version.json
通道 3：https://api.github.com/repos/{owner}/{repo}/releases/latest
```

> 说明：通道 3 返回的是 GitHub Release 对象而非 `version.json`，由 `DefaultUpdateRepository` 转换为 `VersionInfo`（映射关系见第四节）。

## 二、`version.json` 字段表

文件位置：`release/version.json`（`main` 分支根目录下的 `release/`）。客户端只读取以下 6 个字段，多字段会被 JSON 解析器忽略（`Json { ignoreUnknownKeys = true }`）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `versionCode` | Int | 是 | 远程版本号。大于本地 `BuildConfig.VERSION_CODE` 才提示更新 |
| `versionName` | String | 是 | 展示用版本名，如 `1.0.0` |
| `downloadUrl` | String | 是 | APK 直链，使用 Release 资产 ASCII 名 `daoshu-compass-v{versionName}.apk` |
| `changelog` | String | 否（默认 `""`） | 更新说明，空时对话框显示“本次更新未提供说明。” |
| `forceUpdate` | Boolean | 否（默认 `false`） | 为 `true` 时对话框不提供“稍后”按钮 |
| `minSupportedVersion` | Int | 否（默认 `1`） | 最低可支持 `versionCode`；本地低于该值时同样强制更新 |

示例（与仓库当前 `release/version.json` 逐字一致，可 `cat release/version.json` 核对）：

```json
{
  "versionCode": 1000,
  "versionName": "1.0.0",
  "downloadUrl": "https://github.com/helloword4381/DaoShuLuoPan/releases/download/v1.0.0/daoshu-compass-v1.0.0.apk",
  "changelog": "首个正式版：四层罗盘表盘（360°刻度/二十八宿/六十甲子/二十四山+八卦）、传感器融合与最短路径平滑、GeomagneticField 磁偏角、DataStore 设置持久化、三级降级自动更新与 APK 安装。",
  "forceUpdate": false,
  "minSupportedVersion": 1
}
```

强制更新判定（`DefaultUpdateRepository.isForceUpdate`）：

```text
强制更新 = info.forceUpdate == true  或  本地 BuildConfig.VERSION_CODE < info.minSupportedVersion
```

> **通道 3 的已知限制**：GitHub Releases API 不返回 `forceUpdate` / `minSupportedVersion`，组装 `VersionInfo` 时固定为 `false` / `1`；`versionName` 取 `tag_name` 去掉前缀 `v`（为空时 `unknown`），`versionCode` 由 tag 推断（`major*1000 + minor*10 + patch`，例如 `v1.0.1` → `1001`；无法推断时回退 `1000`）。因此**强制升级仅在通道 1/2（`version.json`）可用时生效**。

## 三、状态机（`UpdateState`）

| 状态 | 字段 | 触发时机 | UI 表现 |
|------|------|----------|---------|
| `Idle` | — | 初始状态 / `reset()` 后 | 设置页显示“尚未检查更新” |
| `Checking` | — | `checkForUpdate()` 执行中 | “正在检查更新…” |
| `UpToDate` | `localVersionName`, `channel` | 远程 `versionCode` 不大于本地，或通道返回 404 | “已是最新版本（{版本}）· {通道}” |
| `Available` | `info`, `channel`, `apkSizeBytes` | 远程版本更高 | 弹出更新对话框（版本号 / 更新说明 / APK 大小） |
| `Downloading` | `progressPercent`, `downloadedBytes`, `totalBytes` | `downloadApk()` 进度回调 | 对话框内进度条与字节数 |
| `Downloaded` | `apkFile` | 下载并校验通过 | 提示即将调起系统安装器 |
| `Failed` | `message`, `channel` | 三级通道全部失败，或下载/校验失败 | 显示失败原因与“重试”按钮 |

`apkSizeBytes` 的来源：**通道 3** 可取到 `assets[0].size`；**通道 1 / 2** 无法获知时填 `0`（UI 显示“未知”）。

## 四、通道 3（GitHub Releases API）字段映射

```text
tag_name                            → versionName（去掉前缀 v）
body                                → changelog
assets[0].browser_download_url      → downloadUrl
assets[0].size                      → apkSizeBytes
versionCode                         → 从 tag 数字推断；取不到时使用 1000
```

## 五、HTTP 状态与异常处理

| 情况 | 处理 | 结果 |
|------|------|------|
| 200 + 合法 JSON | 采用该通道结果 | `Available` 或 `UpToDate` |
| 404 | 该通道视为“暂无更新”，不再降级（`ProbeOutcome.None`） | `UpToDate(localVersionName, channel)` |
| 403 / 429（GitHub API 限流） | **降级下一通道** | 继续尝试通道 2 → 3 |
| 其他非 2xx（5xx 等） | 降级下一通道 | 同上 |
| 超时 / DNS / 连接中断（`IOException`） | 降级下一通道 | 同上 |
| JSON 解析失败（`SerializationException`） | 视为该通道失败，降级 | 同上 |
| 通道 1/2 的 `downloadUrl` 为空 | 视为该通道不可用，降级 | 同上 |
| 通道 3 的最新 Release 无 APK 资产 | 视为该通道不可用，降级 | 同上 |
| 三级全部失败 | 终止 | `Failed(message, channel = 最后尝试的通道)` |

> 下载阶段的失败信息归属：`Failed.channel` 取“最近一次成功检查所用的通道”（代码中为 `activeChannel`），非通道相关失败时为 `null`。

其他网络策略（实现于 `di/NetworkModule.kt` 与 `DefaultUpdateRepository`）：

| 策略 | 取值 / 说明 |
|------|-------------|
| OkHttp 磁盘缓存目录 | `context.cacheDir/http_cache`（`NetworkModule.HTTP_CACHE_DIR`） |
| 缓存容量 | 8 MiB（`HTTP_CACHE_SIZE_BYTES`） |
| 检查请求头 | `Cache-Control: public, max-age=300`（`CACHE_CONTROL_VALUE`） |
| 下载请求头 | `Cache-Control: no-cache` |
| 超时 | 连接 10s / 读 30s / 写 30s / 整调用 60s |
| 重定向 | 跟随（含 SSL 重定向，代理通道需要） |
| User-Agent | `DaoShuCompass/{BuildConfig.VERSION_NAME}` |
| 请求头 | `Accept: application/json, text/plain, */*` |
| 客户端单例 | 由 Hilt 注入，仓库内**不得** `new OkHttpClient()`（`DefaultUpdateRepository` 构造器注入 `OkHttpClient` 与 `Json`） |
| 并发保护 | 检查与下载各自加 `Mutex`（`checkMutex` / `downloadMutex`），下载进行中不打断 |

缓存的意义：GitHub API 未认证请求限流为 60 次/小时，`Cache-Control` 配合磁盘缓存可显著减少真实请求，降低 403 概率。

## 六、APK 下载

| 项目 | 取值 |
|------|------|
| 下载实现 | OkHttp + 进度回调（`Downloading` 状态按 1% 或每 64 KB 更新一次） |
| 存储目录 | `context.cacheDir/apk/` |
| 文件名 | `daoshu-compass-v{versionName}.apk` |
| 写入方式 | 先写 `.part` 临时文件，校验通过后改名 |
| 体积校验 | 已知 `size > 0` 且下载结果偏差 > 10% 判为失败（`Failed`） |
| 安装触发 | **不在** `data/update` 内触发安装；由 UI 调用 `ApkInstaller` |

`FileProvider` 配置：

| 项目 | 取值 | 位置 |
|------|------|------|
| authority | `com.daoshu.compass.fileprovider` | `AndroidManifest.xml`（`${applicationId}.fileprovider`）与 `BuildConfig.FILE_PROVIDER_AUTHORITY` |
| paths 资源 | `@xml/file_paths` | `app/src/main/res/xml/file_paths.xml` |
| 已声明路径 | `cache-path`：`apk/`、`.`；`external-cache-path`：`apk/`；`files-path`：`apk/` | 同上 |

## 七、安装与“未知来源”授权

`ApkInstaller` 的职责与适配：

| 方法 | 作用 | 版本适配 |
|------|------|----------|
| `canRequestPackageInstalls(context)` | 查询是否已授予“安装未知应用”（`PackageManager.canRequestPackageInstalls()`） | Android 8.0+（API 26） |
| `openInstallPermissionSettings(context)` | 跳转 `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES` 授权页 | Android 8.0+ |
| `install(context, apkFile)` | `FileProvider.getUriForFile` + `Intent.ACTION_VIEW` + `application/vnd.android.package-archive` + `FLAG_GRANT_READ_URI_PERMISSION` | Android 11–15 |
| `ensureNotificationChannel(context)` | 创建下载完成通知渠道（ID `daoshu_update`） | Android 8.0+ 渠道；Android 13+ 需 `POST_NOTIFICATIONS` |
| `notifyDownloadComplete(context, apkFile)` | 发送下载完成通知 | Android 13+ 需通知权限 |

清单声明（`app/src/main/AndroidManifest.xml`）：

```xml
<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

用户操作路径：点击“立即更新” → 若未授权则跳转“安装未知应用”设置页 → 返回后重新点击 → 下载 → 通知提示 → 调起系统安装器确认安装。
Android 12+ 的 `PendingIntent` 必须带 `FLAG_IMMUTABLE`；逐版本适配细节见 [Android11-15适配.md](Android11-15适配.md)。

## 八、通道排障手册

### 8.1 逐个通道验证（用浏览器或 curl）

```bash
# 通道 1：加速代理
curl -sS -i "https://ghfast.top/https://raw.githubusercontent.com/helloword4381/DaoShuLuoPan/main/release/version.json"

# 通道 2：raw.githubusercontent
curl -sS -i "https://raw.githubusercontent.com/helloword4381/DaoShuLuoPan/main/release/version.json"

# 通道 3：GitHub Releases API
curl -sS -i -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/helloword4381/DaoShuLuoPan/releases/latest"
```

```powershell
# Windows PowerShell 等价命令
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/helloword4381/DaoShuLuoPan/main/release/version.json" -UseBasicParsing | Select-Object -ExpandProperty Content
Invoke-RestMethod -Uri "https://api.github.com/repos/helloword4381/DaoShuLuoPan/releases/latest" -Headers @{ "User-Agent" = "DaoShuCompass" } | Select-Object tag_name, assets
```

```bash
# 校验 downloadUrl 是否可下载（只取头）
curl -sSIL "https://github.com/helloword4381/DaoShuLuoPan/releases/download/v1.0.0/daoshu-compass-v1.0.0.apk"
```

### 8.2 常见现象对照表

| 现象 | 可能原因 | 排查 / 处置 |
|------|----------|-------------|
| 一直提示“已是最新版本”但确实发了新版 | `release/version.json` 未推到 `main`，或 `versionCode` 未增大 | 用 8.1 的通道 1/2 请求确认内容；核对与 `app/build.gradle.kts` 的版本号差异 |
| 日志出现 `403` / `429` | GitHub API 未认证限流（60 次/小时） | 属预期：会自动降级到通道 2；减少手动“立即检查更新”频次 |
| 提示“检查失败” | 三级通道全部失败（无网络 / DNS 污染 / 代理不可达） | 用 8.1 命令在本机与设备网络分别验证；确认 `INTERNET`、`ACCESS_NETWORK_STATE` 已声明 |
| 通道 3 解析不到 APK | Release 未上传资产或资产名不是 ASCII 名 | Release 资产必须为 `daoshu-compass-v{versionName}.apk` |
| `apkSizeBytes = 0` | 走的是通道 1 / 2（无法获知体积） | 属预期；对话框显示“未知”，不影响下载 |
| 下载失败：体积偏差 > 10% | 代理返回了截断内容或错误页 | 优先走通道 2/3；确认 `downloadUrl` 指向真实 APK |
| 下载完成但无安装界面 | 未授予“安装未知应用” | 设置页重新触发，`ApkInstaller.openInstallPermissionSettings` 跳转授权 |
| Android 13+ 无下载完成通知 | 未授予 `POST_NOTIFICATIONS` | 在系统设置中为应用开启通知权限 |
| 应用被杀后下载中断 | 当前实现为 OkHttp + 通知，**未使用前台服务** | 保持应用前台完成下载；若改为前台服务下载，需按 Android 14+ 声明 `dataSync` 类型 |
| 真机无法访问代理域名 | 部分网络对 `ghfast.top` 不通 | 属预期：三级降级会自动回退通道 2 |

### 8.3 版本发布后端的“提前推送”策略

工作流在**创建 Release 之前**先把 `release/version.json` 推送回 `main`（`git fetch` + `git rebase` + `git push`，提交信息带 `[skip ci]` 防止递归触发），这样客户端在 Release 创建完成的那一刻即可通过通道 1/2 读到新版本；推送失败只告警、不中断构建，人工再补推一次即可。
